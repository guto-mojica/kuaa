{# Left pane — query queue with filter tabs + toggles. Rows arrive fully resolved as ``queue_rows`` (kuaa.eval.queue_view.build_queue_rows): status, pips and the n/m counter are all computed against THIS grader and the CURRENT pool. The template derives nothing. It used to read grades_by_query, which bags every judgment in the run — including ones taken against pools the run has replaced — and so rendered counters like 56/22 and marked rows done that the resume cursor still had candidates for. Filter tabs (All / Pending / Conflict) drive a reactive ``filter`` signal; each row's ``x-show="visible($el)"`` re-evaluates and hides itself when its ``data-status`` / ``data-conflict`` don't match. The search input feeds the same predicate via the ``search`` signal. The filter is seeded from ``?filter=`` and every row link carries the live value back, because opening a query is a full page load: local Alpine state would reset on each click, which is what made the tabs look decorative — you could set one, but never grade under it. Toggles (Blind mode / Compare annotator) use the .swt switch primitive in eval.css and are x-model-bound to the evalApp component (eval.js); the keyboard router (B / C) flips the same signals, so keypress and click stay in sync. The filter / search signals stay LOCAL to this aside to keep queue-only UI state out of the keyboard router's payload. #}
